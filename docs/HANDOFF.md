## ۱. در یک نگاه — چه چیزی الان زنده است

روی `212.80.8.87` (اوبونتو ۲۲.۰۴، ۸ هسته، ۱۶ گیگ):

- **۷ سرور CS:Source v92** (buildid `6953255`)، همه روی همان یک IP، هرکدام پورتِ یکتا، همه با systemd و **در بوت خودکار بالا می‌آیند** (با reboot واقعی تست شد).
- **پایهٔ مشترک** `/opt/css/base` + overlayfs جدا برای هر نمونه.
- **`cg-agent`** (سرویسِ احرازِ هویت، Go) روی `127.0.0.1:8480` — الان در حالتِ **stub** (هر بلیتی را قبول می‌کند) تا لانچر و API آماده شوند.
- **SourceMod 1.12.0-git7179** (میخ‌کوب‌شده) + Metamod 1.12 + RIPExt + SMAC + Lilac (فقط‌لاگ).
- **MariaDB**، **nginx FastDL** (با محدودیتِ نرخ ۱.۵ مگابایت/ثانیه)، **فایروال nftables**، **دیده‌بانِ A2S**، چرخشِ لاگ/دمو.
- پلاگین‌های خودمان: `chogan_auth`، `chogan_ratepolicy`، `chogan_dm`، `chogan_gungame`، `chogan_weaponrestrict`، `chogan_match`.

**مصرفِ منابع در حالتِ خالی (پس از رفعِ رگرسیونِ ۲۰ اوت):** کلِ هفت سرور روی هم **۱۸٪ یک هسته** از ۸ هسته، ۱٫۶ گیگ رم از ۱۶، دیسک ۲۱٪. (پیش از رفع: ~۷٫۵ هسته. علت: srcds با stdin روی tty حلقهٔ کنسول را busy-poll می‌کرد — جزئیات در `docs/decisions.md` D-008.)

**آنچه هنوز ثابت نشده:** اینکه یک کلاینتِ واقعیِ non-Steam بتواند وصل شود (بخش ۲.۵ — تنها موضوعِ بازِ مهم).

## ۲. برای سشنِ پلتفرم چوگان — قراردادِ یکپارچه‌سازی

### ۲.۱ جریانِ کلیِ ورودِ بازیکن

```
بازیکن در لانچر با شمارهٔ تلفن لاگین می‌کند
        ↓
لانچر از API چوگان لیستِ سرورها را می‌گیرد        (API شما)
        ↓
بازیکن سروری را انتخاب می‌کند
        ↓
لانچر از API یک «بلیت» (ticket) برای همان سرور می‌گیرد   (API شما)
        ↓
لانچر کلاینت CS:S را اجرا می‌کند و پیش از connect:
        setinfo lt <ticket>
        connect 212.80.8.87:27017
        ↓
سرور بلیت را می‌خواند و به cg-agent می‌دهد → cg-agent از API شما می‌پرسد
        ↓
حساب bind می‌شود (یا بازیکن kick/مهمان می‌شود)
```

### ۲.۲ لیست سرورها (برای منوی لانچر)

| server_id | نام | پورت اتصال | slots | tickrate |
|---|---|---|---|---|
| `pub1` | Public #1 | **27017** | 32 | 66 |
| `pub2` | Public #2 | **27018** | 32 | 66 |
| `dm` | DeathMatch | **27019** | 24 | 66 |

> ⚠️ **A2S (پرس‌وجوی server browser) از اینترنت بسته است** — عمداً، طبق اسپک. یعنی لانچر **نمی‌تواند** تعدادِ بازیکن/نقشه را با کوئریِ مستقیم بگیرد. دو راه: (الف) لانچر لیست و آمار را از API چوگان بگیرد و API آن را از سرور بپرسد، یا (ب) IP سرورِ API شما را در whitelistِ فایروال اضافه کنیم:
> ```bash
> nft add element inet filter monitoring_v4 { <IP سرور API شما> }
> ```
> (برای دائمی‌شدن در `/etc/nftables.conf` هم اضافه شود.)

### ۲.۳ قراردادِ بلیت — دقیق

- لانچر **باید** `setinfo lt <ticket>` را **پیش از** `connect` اجرا کند. کلیدی که بعد از connect ساخته شود نادیده گرفته می‌شود.
- نامِ کلید دقیقاً `lt` است و در پلاگین ثابت است (اگر نامِ دیگری می‌خواهید بگویید تا در `chogan_auth.sp` عوضش کنیم).
- **🔴 حداکثر طولِ بلیت: ۲۵۹ کاراکتر.** این را واقعاً اندازه گرفتیم ([`evidence/21-setinfo-length-limit.txt`](evidence/21-setinfo-length-limit.txt)): موتورِ بازی مقدار را در بافرِ ۲۶۰ بایتی می‌برد و **بی‌صدا truncate می‌کند** — نه خطایی، نه قطعی. یعنی:
  - **JWT نگذارید.** JWTها معمولاً ۲۰۰ تا ۵۰۰+ کاراکترند و با اضافه‌شدنِ claim بزرگ‌تر می‌شوند → یک روز به‌طور تصادفی از ۲۵۹ رد می‌شود و همهٔ ورودها «invalid» می‌شوند و کسی نمی‌فهمد چرا.
  - **بلیتِ کوتاه و opaque** بدهید (پیشنهاد: ۳۲ تا ۶۴ کاراکتر تصادفیِ base64url). خودِ `cg-agent` در حالتِ local بلیتِ ~۴۳ کاراکتری می‌سازد.
  - محدودیتِ طول را **در خودِ لانچر/API** اعمال کنید؛ سرور نمی‌تواند truncate را تشخیص دهد.
- ویژگی‌های بلیت که سمتِ سرور فرض شده (و `cg-agent` در حالتِ local دقیقاً همین را پیاده کرده):
  - **یک‌بارمصرف** (single-use)
  - **TTL کوتاه، ~۹۰ ثانیه**
  - **محدود به یک `server_id`** — بلیتِ `pub1` روی `dm` رد می‌شود (`reason: scope`)
  - سمتِ سرور فقط **hash** ذخیره می‌شود (متنِ خام هرگز)
  - مصرف با یک UPDATE اتمیک: `UPDATE tickets SET used_at=NOW() WHERE hash=? AND used_at IS NULL AND exp>NOW() AND server_id=?`

### ۲.۴ APIای که باید بسازید (`api.chogan.games`)

`cg-agent` وقتی روی `mode = "remote"` برود، دقیقاً این را صدا می‌زند:

```http
POST https://api.chogan.games/v1/servers/redeem
Authorization: Bearer <توکنِ این سرور>
Content-Type: application/json

{"ticket":"<مقدارِ lt>","server_id":"pub1","ip":"1.2.3.4","authid":"STEAM_0:1:123","name":"Player"}
```

پاسخِ موفق (همیشه HTTP **200**):
```json
{"ok":true,"account_id":1337,"display_name":"Neo","phone_masked":"+989*******67"}
```
پاسخِ رد (باز هم HTTP **200**):
```json
{"ok":false,"reason":"used"}
```
`reason` یکی از: `invalid` | `expired` | `used` | `scope`

**قواعدی که رعایتشان مهم است:**
- برای نتیجهٔ سیاستی **هرگز 5xx ندهید** — همیشه 200 با `ok:false`. کدهای 5xx به‌معنیِ «API خراب است» تفسیر می‌شوند و بازیکن (در حالتِ نرم) به‌عنوان مهمان وارد می‌شود.
- `account_id` **هویتِ اصلی** است. بن، ادمین و آمار باید به این کلید بخورد، **نه به SteamID** (SteamIDِ non-Steam جعل‌شدنی است).
- شمارهٔ تلفنِ کامل را برنگردانید؛ `phone_masked` کافی است.
- زمانِ پاسخ: تایم‌اوتِ هر تلاش ۳ ثانیه است، یک retry. اگر کند باشید، بازیکن‌ها با تأخیرِ join مواجه می‌شوند (circuit breaker بعد از ۵ خطا در ۳۰ ثانیه باز می‌شود).

رویدادها (fire-and-forget، برای آمار):
```http
POST https://api.chogan.games/v1/servers/events
{"server_id":"pub1","account_id":1337,"type":"connect","payload":{"map":"de_dust2"}}
```
> مسیرِ `/v1/servers/events` یک **فرض** بوده؛ اگر مسیرِ دیگری می‌خواهید فقط در `/etc/cg-agent/config.toml` کلیدِ `api.event_path` را عوض کنید.

**سوئیچ به API واقعی** (وقتی آماده شد) — یک خط:
```toml
# /etc/cg-agent/config.toml
mode = "remote"          # قبلاً "stub"
[api]
token = "<توکنِ سرور>"
```
سپس `systemctl restart cg-agent`. نیازی به لمسِ هیچ سروری نیست.

### ۲.۵ 🔴 مهم‌ترین تصمیمِ باز: کلاینتِ non-Steam

**مسئله:** بازیکنان کلاینتِ رسمیِ Steam ندارند. سرور باید کلاینتِ non-Steam را بپذیرد. ما RevEmu (نسخهٔ bir3yk) را روی سرور نصب کردیم و **درست بار می‌شود**، اما نتوانستیم اثبات کنیم یک کلاینت واقعاً وصل می‌شود — چون بلیتِ معتبرِ RevEmu را بدونِ کلاینتِ اصلیِ آن نمی‌شود ساخت (کلاینتِ RevEmu بسته و Themida-packed است و بلیت را از سریالِ هارد می‌سازد).

**دو راهِ پیشِ رو — این تصمیمِ شماست:**

| | گزینهٔ A: RevEmu | گزینهٔ B: `sm-ext-connect` + `sv_nosteam` (توصیهٔ من) |
|---|---|---|
| سمتِ کلاینت | باید کلاینتِ RevEmuِ **هم‌نسخه** را در لانچر بسته‌بندی کنید | هر کلاینتِ v92 (حتی ساده/Goldberg) |
| وابستگی بیرونی | به بک‌اندِ bir3yk (روسی) و هم‌خوانیِ نسخه | هیچ — کاملاً محلی |
| کنترلِ شما | کم | کامل (شما هر دو سر را دارید) |
| وضعیت روی سرور | ✅ نصب و فعال | ❌ باینریِ آماده GLIBC 2.38 می‌خواهد، اوبونتو ۲۲.۰۴ ما ۲.۳۵ دارد → باید از سورس build شود |

**توصیه:** گزینهٔ **B**. چون این یک پلتفرمِ بسته است، هویت روی حسابِ تلفن است (نه SteamID) و RevEmu فقط «درِ ورودی» است؛ وابسته‌کردنِ درِ ورودی به یک سرویسِ شخص‌ثالثِ خارجی ریسکِ بی‌دلیلی است.

**آنچه از شما لازم داریم تا این بسته شود** (هرکدام کافی است):
1. بگویید کلاینتِ لانچر دقیقاً چه چیزی است (RevEmu؟ کدام نسخه؟) تا سرور را با همان تنظیم کنیم؛ **یا**
2. تأیید کنید که برویم سراغ گزینهٔ B (بیلدِ `sm-ext-connect` روی ۲۲.۰۴ — کارِ یکی دو ساعته)؛ **یا**
3. یک کلاینتِ تستیِ v92 در اختیارمان بگذارید تا همان‌جا تست کنیم.

### ۲.۶ نکاتِ دیگرِ لانچر

- **FastDL**: `sv_downloadurl` روی `http://212.80.8.87/cstrike` تنظیم است. اگر محتوای سفارشی (نقشه/مدل) اضافه شد باید در `/opt/css/content/cstrike/` گذاشته و `css-fastdl-sync` اجرا شود.
- **نسخهٔ کلاینت باید v92 باشد** (`PatchVersion=6630498`). کلاینتِ v93/v34 وصل نمی‌شود.
- بازیکن بدونِ بلیت: در حالتِ پیش‌فرض (`cg_auth_mode 1` نرم) به‌عنوان **مهمان** وارد می‌شود. اگر می‌خواهید ورود بدونِ لانچر ممنوع باشد، `cg_auth_mode 2` (سخت) را بزنید.
- **reconnect دستی**: اگر بازیکن دکمهٔ reconnect بزند همان بلیتِ مصرف‌شده را دوباره می‌فرستد. این حالت را هندل کرده‌ایم (کشِ ۱۰ دقیقه‌ای بر اساس IP + اثرانگشتِ بلیت) — بازیکن kick نمی‌شود. لازم نیست لانچر کاری کند، ولی اگر بتواند بلیتِ تازه بدهد بهتر است.

## ۳. برای سشن‌های بعدیِ Claude Code — قوانینی که نباید بشکنید

0. **هرگز به srcds ترمینال ندهید.** stdin باید `/dev/null` باشد. با `-console` و یک tty، srcds حلقهٔ کنسولِ تعاملی را busy-poll می‌کند و **به‌ازای هر نمونه یک هستهٔ کامل** می‌سوزاند حتی وقتی سرور خالی است (اندازه‌گیری‌شده: ۹۵٪ با tty، ۳٪ بدونش). در `css@.service` مقدارِ `StandardInput=null` پین شده — برش ندارید. لاگِ بازی در `cstrike/logs/` نوشته می‌شود و به journald نیازی نیست.
1. **SourceMod را ارتقا ندهید.** روی `1.12.0-git7179` قفل است. هر بیلدِ جدیدتر روی v92 **اصلاً بار نمی‌شود** (`ServerGameClients005`). جزئیات: `docs/decisions.md` D-005.
2. **پایهٔ مشترک را وقتی نمونه‌ای بالاست تغییر ندهید.** `lowerdir` نباید حین mount عوض شود. یک‌بار این کار systemd را در وضعیتِ خرابِ mount-namespace انداخت و همهٔ سرورها با `226/NAMESPACE` مردند؛ فقط reboot درستش کرد (D-007). ترتیبِ درست:
   ```bash
   systemctl stop 'css@*' ; systemctl stop 'css-overlay@*'
   # ... تغییر در /opt/css/base ...
   /opt/css/bin/css-base-fixperms      # اگر overlay سوار باشد خودش رد می‌کند
   # ... سپس start
   ```
3. **رمزِ SSH و password-login را دست نزنید.** قانونِ صریحِ صاحبِ سرور. کلیدِ ما اضافه شده، رمز دست‌نخورده.
4. **رازها در مخزن نروند.** رمزِ دیتابیس/RCON در `/opt/css/etc/secrets/` روی سرور است و در `.gitignore`.
5. **کامپایلِ پلاگین روی خودِ سرور** انجام می‌شود (`scripts/build-plugins`) با همان spcompِ نسخهٔ ۷۱۷۹.
6. **باینریِ آمادهٔ افزونه‌ها را بی‌آزمایش استفاده نکنید** — بیشترشان برای Ubuntu 24.04/GLIBC 2.38 بیلد شده‌اند و روی این باکس بار نمی‌شوند. به همین دلیل همهٔ پلاگین‌های حالتِ بازی را SourcePawnِ خودبسنده نوشتیم.

**ابزارهایی که ساخته شده و باید ازشان استفاده کنید:**

| ابزار | کار |
|---|---|
| `scripts/rsh` / `scripts/rroot` | اجرای فرمان روی سرور (کاربر / روت) |
| `scripts/deploy-server-tree` | پوش کلِ `server/` روی سرور (tarball، سریع) |
| `scripts/build-plugins` | کامپایلِ `.sp` روی سرور و برگرداندنِ `.smx` |
| `scripts/build-cg-agent` | بیلدِ Goی سرویسِ احراز روی سرور |
| `scripts/srcclient/srcclient.py` | **کلاینتِ تستِ سطحِ پروتکل** — بدونِ نیاز به CS:S واقعی، connect/handshake/netchannel واقعی می‌زند. ابزارِ اصلیِ تستِ ما. |
| `/opt/css/bin/css-rcon` | RCON از روی خودِ باکس |
| `/opt/css/bin/css-loadtest` | تستِ بار (probe 4) |
| `/opt/css/bin/css-genconf` | رندرِ کانفیگِ یک نمونه از روی قالب‌ها |

## ۵. ریسک‌ها و چیزهایی که مدیرِ پروژه باید بداند

1. **زنجیرهٔ ورود تا «آخرین متر» تست شده، نه تا انتها.** احرازِ هویت، بلیت، خطای API، kick/مهمان — همه با کلاینتِ سطحِ پروتکل تست شد. آنچه تست نشده فقط این است که یک کلاینتِ گرافیکیِ non-Steam بتواند از درِ ورودی رد شود (بخش ۲.۵). این ریسکِ شمارهٔ یکِ پروژه است.
2. **وابستگیِ نسخه‌ای سفت:** SourceMod روی یک بیلدِ خاصِ فوریهٔ ۲۰۲۵ قفل است و v92 خودش یک بیلدِ ۲۰۲۱ است. اکوسیستمِ CS:S در حالِ مرگ است؛ هر ابزارِ جدیدی که می‌آید احتمالاً روی این استک کار نمی‌کند. این را در برنامه‌ریزیِ بلندمدت لحاظ کنید.
3. **ظرفیتِ سخت‌افزار:** با ۱۴۹ باتِ پُر، ~۷.۵ از ۸ هسته مصرف شد. بات‌ها از بازیکنِ واقعی سنگین‌ترند، پس ظرفیتِ واقعی بیشتر است — ولی حاشیهٔ زیادی نداریم. اگر هر ۷ سرور هم‌زمان پُر شوند، سرورهای ۱۰۰-تیک به ۶۶ می‌افتند.
4. **هیچ سیستمِ مسابقهٔ آماده‌ای برای CS:S در ۲۰۲۶ وجود ندارد** (get5/MatchZy فقط CS:GO/CS2 هستند). ما یک پلاگینِ کمینه نوشتیم (ready-up، راندِ چاقو، LO3، امتیاز، تایم‌اوت). اگر امکاناتِ حرفه‌ای‌تر (بازگردانیِ راند، آمارِ کامل) خواستید، کارِ توسعهٔ جداست.
5. **دیسک:** ۱۲ از ۵۹ گیگ مصرف شده. دموهای SourceTV سقف دارند (۳ گیگ/نمونه، ۱۴ روز) ولی اگر مسابقات زیاد شد باید پایش شود.

## ۶. جمع‌بندیِ سه‌خطی

سمت‌سرور **کامل و زنده** است: هفت سرور، احرازِ هویتِ تلفنی، ضدتقلب، سخت‌سازی، و مقاومت در برابرِ reboot — همه با شواهدِ خام.
تنها چیزی که برای بازیِ واقعیِ بازیکنان کم است، **تصمیم و تحویلِ کلاینتِ non-Steam** (بخش ۲.۵) و **پیاده‌سازیِ endpointِ redeem** در API چوگان (بخش ۲.۴).
تا آن زمان سرورها در حالتِ stub کاملاً قابلِ استفاده و تست‌اند.
